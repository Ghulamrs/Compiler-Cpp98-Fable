clang -std=c++98 or Visual Studio's clang-cl where cl deviates from the standard)

cppparse release 6.0 (tag v6.0, 2026-11-04) plus the commits since: the review rows P1-P19 at the end of
docs/next-targets.md and their fixes up to fe28628 (2026-11-10), and the mending of 2026-11-12 (rows P2-P4, P6, P7,
P9, P14, R5, M12b, B1 and G1-G7) with G8 (2026-11-13), the round of 2026-11-13 (rows G9-G19), the rows of

version stays 6.0. The state of every item below is kept in docs/next-targets.md under the row named in brackets;

WHAT HOLDS (verified on these commits in a clean worktree)
- Self-hosting: the version 6 pipeline (--compile6) compiles cppparse's 58 own sources and libcpp, and the self-built
  compiler reproduces every object and listing byte for byte through generation two, at -O0 and at -O2 (selfhost.ps1
  -Lvl 0 and -Lvl 2); the 21-group suite passes under the MSVC-built compiler and under the -O2 self-built one.
  Linked by GRIDE's link in place of Microsoft's (selfhost.ps1 -Linker gride; row P1, stage 0a) the two generations
  are one exe byte for byte at both levels, and the suite passes under that compiler as well.
- The language: classes in every inheritance shape cl lays out (virtual bases, vtordisp and covariant thunks, pointers
  to members in cl's representations), templates (class, function and member templates, partial and explicit
  specialisations, explicit instantiation definitions, SFINAE, partial ordering, deduction from function types),
  exceptions in the table model with destructors on every path, and in cl's own model (--eh=cl) for programs with
  cl-compiled C++ code, where they cross both ways, RTTI through vcruntime, the preprocessor with
  trigraphs, digraphs and the alternative tokens, access control, cl /W4's warnings, 64-bit constant expressions,
  static locals with cl's thread-safe protocol, argument-dependent lookup, the standard conversions and ranking
  rules the samples cover; objects link with cl's at every layout and decorated name the samples cover.
- The library: the 32 C++ headers of C++98 and <strstream>, the 18 <cxxx> headers, basic_string and wstring, the
  stream templates over basic_streambuf (narrow and wide, string and file streams), locale with ctype, numpunct,
  num_put, num_get, collate, codecvt and the time, monetary and messages facets, for the classic locale and for the
  C runtime's named ones, complex, valarray, bitset, the containers and algorithms, nothrow new, bad_alloc,
  set_new_handler, set_terminate and uncaught_exception.

WHAT IS LEFT
1. Valid C++98 refused with an error: the associative containers have no constructor taking a comparison object,
   no key_comp, value_comp or relational operators (row G34, found by row G31's probes; the range members of every
   container take any iterator since row G31). Not refused but chosen wrongly: of several partial specialisations
   that match, the first declared is taken, not the most specialised (row G32, 14.5.4.2; found by row G31).
   (Pointers to members convert along non-virtual bases between every pair of inheritance models; the conversions
   through a virtual base that stay S132 are ill-formed in C++98, 4.11/2, and cl's extension: memptr-refused.cpp.)
2. Ill-formed code accepted without a diagnostic:
   - static_cast of an integer to a pointer (row G33, 5.2.9; cl C2440), found by row G31.
   - access control leaves out what only one of cl and clang refuses: the member types in the signature of a function
     template (clang refuses, cl accepts), a thrown object with a private destructor (clang only), and every
     specialisation of a befriended function template name counts as a friend, as with cl. A class with a friend
     declared by a qualified name that only a template could match is not checked (M12, row G14: the rest is checked
     since 2026-11-18).
   - a class that is completed later in the unit counts as complete from its first declaration on: `struct I;
     void f() { I x; }  struct I { };` compiles, and so does a handler for I* or I& there (3.2/4, 15.3/1; cl and
     clang refuse; found by row G29's probes. The bodies of functions are analysed after the unit's declarations).
3. Different from cl where C++98 leaves it unspecified or undefined (stays): the arguments of a call are evaluated
   left to right, cl right to left (A5, 14d); NRVO in nested blocks at -O2, an elision cl makes and 12.8 permits; the
   copy order when a by-value handler rethrows into another (15.2 and 15.3's order; cl copies before it unwinds);
   (double)~(int)3e9 and (int)3e9 * x fold the narrowed value (undefined, 4.9/1).
4. Won't fix: dynamic exception specifications are parsed and ignored, as cl does (C4290), so std::unexpected is
   never called (15.4; m5); export (as every compiler); other targets (x86_64-linux is front end only).
5. Deferred: cl has two type descriptors for a pointer to a function with an array parameter, one for each way of
   writing it, and instantiates a function template for each; cppparse has one of each, spelled plainly (row G15,
   by design: the two are one type);
   the size of --eh=cl's unwind data, which keeps the table model the default (2.5 to 7.5 % more object bytes): FH4's
   compressed tables in place of FH3's (row G26: the maps are two thirds of what the model adds in sample-eh's
   probe) and the funclets' unwind records, equal ones written once and fewer cleanups with a frame (row G27: the
   other third), both measured against cl on 2026-11-19; in the default model an exception that reaches a cl-compiled
   frame with something to destroy or a handler stops with the runtime's message, as designed (M7); CodeView types
   and locals (the line tables exist; M10: its design, docs/design-codeview.md of 2026-11-19, is reviewed and
   has the go-ahead of 2026-11-20; of its stages, the CodeView code is in cppparse/cv and the comparator of "debug
   information changes no code", scripts\cvsame.ps1, exists, a procedure's symbol shows cl's name for it, and with -g
   an object has its types (.debug$T), its globals, static members and static locals, and since stage 2 (2026-11-24)
   every function's parameters and locals, each in its place at -O0 (test 21, the value harness); at -O1 and up
   they are listed without a place until the design's stage 3); vftables stay static symbols in mixed links, by
   design (row 20); an
   exception edge from every call in the IR and the optimiser (design-table-exceptions.md section 7), the remaining
   code-size lever now that the plan's rows A to H are done or measured.
6. Library: messages has no catalogues under any locale name, and the wide file streams convert through the C
   runtime rather than through the locale's codecvt (C3; the facets of 22.2 for the classic locale since 2026-11-18,
   row G22; named locales, the C runtime's, since 2026-11-20, row G28, which also lists where the library follows
   22.1 and 22.2 and not cl's). (<vector> copy-constructs, assigns and destroys as 23.2.4 says since P9; only
   arithmetic types and pointers are moved bytewise.)
7. The sources against strict C++98: clang -std=c++98 -pedantic reports nothing but long long in the two typedef
   pairs (common/Int64.hpp, include/__config; P4); sandbox/scripts/strict98.ps1 checks it and allows nothing else.
8. Self-hosting boundary: since 2026-11-24 (P1 stages 1 to 3, level 1) the exception runtime runtime/cppparse_rt.cpp
   is compiled by the compiler under test in every self-host generation (__declspec(thread), five intrinsics, the
   /alternatename pragma and the unwind declarations of platform/ are in the compiler; its object has no model mark),
   and selfhost.ps1 runs cl nowhere; the linker and the C runtime are still MSVC's by default (P1: its design,
   docs/design-selfhost.md of 2026-11-19, is reviewed and has the go-ahead of 2026-11-20). Stage 0a of it is done (2026-11-20): selfhost.ps1 -Linker gride links the self-host with GRIDE's
   link, the two generations' exes byte-identical at -O0 and -O2, and the suite passes under the GRIDE-linked
   compiler (harness checks selfhost-gride-O0, selfhost-gride-O2, suite-self-gride; skipped by name where GRIDE is
   not found); Microsoft's link stays the default. GRIDE's link keeps libcpp's replaceable allocation functions
   since 2026-11-24 (request G7 done in GRIDE3: replace.ps1 -Strict holds in both models); open there, request G8: a
   folded static vftable with libcmt's bad_alloc member pulled in (newhandler at -O2 in cl's model).
   GRIDE's runtime underneath (stage 4, with requests G1 and G2 to GRIDE3) and the rest of level 3 are to come. The default command line
   still runs the version 1 to 5 pipeline; the complete compiler needs --compile6 (P19).
9. Limits: a recursive value template 5000 deep fails at the 400-deep expression limit (cl fails too; M13); a class
   template instantiation nested 1000 deep is refused (S148, cl C2999).

Not a gap, checked: "const int ci = 3.0; int a[ci];" is S114, which 5.19/1 requires (a floating literal takes part
only when cast); cl accepts it as an extension (P18).
